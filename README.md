# 🚇 오늘은여기서

친구들의 출발지로 공정한 약속 장소(지하철역)와 귀갓길 막차를 알려주는 Streamlit 웹앱입니다.

## 1. 프로젝트 소개

**목적.** 친구들과 번개 모임을 자주 갖는데, 그 때마다 어디서 만나야 막차 걱정 안 하고 충분히 놀 수 있는지를 고민했습니다.  이렇게 고민하는 시간을 줄여 그 시간에 친구들과 몇 분이라도 더 떠들고 싶어 이 프로그램을 고안하게 되었습니다.

**대상 사용자.** 서울과 경기도에 흩어져 사는 2~3명의 친구 모임. 특히 "몇 시까지 놀 수 있지?"를 매번 직접 찾아보는 경기도 친구.

![정자역에서 귀갓길 막차를 계산한 화면](docs/images/README용사진/app_target_bokjeong.png)

위례 친구가 복정역까지만 가면 되는 경우의 결과(23:24)입니다.

## 2. 실행 방법

```bash
git clone https://github.com/jcy1109/oneul-yeogi.git
cd oneul-yeogi
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

**데모(키 없이):** `.env` 없이 `streamlit run app.py` → `demo_data/` 예시만 쓰는 데모 모드. **저장된 예시 불러오기** → **약속 장소 추천받기** → 1위 정자역. 첫 친구의 "막차로 꼭 도착해야 하는 곳"에 `복정역` → **🌙 막차 확인하기** → 23:24 (빈칸이면 21:43).

**실제 실행:** `.env.example`을 `.env`로 복사해 두 키를 넣고, ODsay 콘솔에 실행 컴퓨터 IP를 등록한 뒤 테스트 모드를 끕니다. ODsay는 하루 30건으로, 추천 1번에 최대 10건, 막차 확인은 친구당 최대 3건을 씁니다.

**테스트:** `for f in test_*.py; do python $f; done`

## 3. 주요 기능

1. **공정한 약속 장소 추천.** 후보역을 친구별 실제 대중교통 시간으로 순위를 매깁니다. ⚖️ 공평하게(가장 오래 걸리는 친구 기준), ⚡ 빠르게(합 기준).
2. **집부터 경로 안내.** 주소로 출발지를 받아 도보 구간부터 환승까지 보여줍니다.
3. **모임 시간 플래너.** 친구별 출발 시각과, 각자의 목표 지점까지 막차를 거꾸로 계산해 "몇 시까지 놀 수 있는지" 알려줍니다.

## 4. 작업 과정과 주요 결정

- **10/14 뼈대:** 좌표 변환, 중심점에서 가까운 후보역 고르기.
- **직선거리 → 실제 시간:** 강남+수원의 중심점 금정은 강남에서 돌아가야 해서 ODsay 소요시간, 캐시, 한도 관리를 넣었습니다.
- **기준 3개 → 2개:** 기준(care, fast, equal)을 강남+수원 데이터로 직접 써보며 비교해 골랐습니다. 직접 써보니 equal이 care와 같은 결과를 내서 공평하게(fair)와 빠르게(fast) 2개로 줄였습니다.
- **출발지 역 → 집 주소:** 실제로는 집에서 출발하므로 주소로 받게 했습니다.
- **맛집 → 모임 시간 플래너:** 직접 써보니 맛집 결과가 대부분 프랜차이즈여서 방향을 바꿨습니다.
- **막차 전 "0단계":** 코딩 전 실제 호출 6건으로 설계 변경(종착역별 막차, 버스 회차점)을 미리 찾았습니다.
- **목표 지점 입력:** 마지막 구간은 택시일 수도 있고 버스 막차는 부정확해서, 친구마다 목표 지점을 정하게 했습니다.

## 7. 효과적이었던 실천

1. **에이전트 보고를 그대로 믿지 않고 직접 대조하기**: 에이전트가 테스트 결과를 보고하면 바로 받아들이지 않고
   직접 검증하였습니다. 좌표는 지도에서, 경로는 카카오맵에서, 막차는 네이버 시간표에서 확인했습니다.
   그 결과 에이전트가 "확정"이라고 했던 3217번 버스 막차가 실제와 1시간이나 차이 나는 오류를 발견했습니다.
2. **코딩 전에 실제 데이터로 먼저 확인하기**: API 설명서만 믿고 코드를 짜지 않고, 실제로 1~6번 정도만
   호출해서 정확한 답이 어떻게 오는지 먼저 확인했습니다. 초반에 틀린 키로 1번 호출했더니 오류인데도
   상태 코드는 정상(200)이였습니다. 또 막차 기능을 코딩하기 전에 API를 6번 호출해 보니,
   '막차' 표시가 붙은 24:22 죽전행은 수원까지 가지 않아서 그대로 썼다면 수원 친구에게 막차를
   44분 늦게 알려줄 뻔했습니다. 적은 호출로 설명서에 없던 함정을 미리 찾아서, 다 만든 뒤에 고치는 일을 줄일 수 있었습니다.
3. **기능 하나마다 테스트하고 커밋하기**: 기능이 하나 완성될 때마다 테스트를 돌리고 GitHub에 커밋했습니다.
   덕분에 맛집 기능처럼 필요 없는 코드를 지울 때도 기록이 남아 있어서 부담이 없었고,
   새 기능을 넣은 뒤 이전 결과(복정역 목표 23:24 등)가 그대로인지 바로 확인할 수 있었습니다.

## 8. 어려웠던 점

1. **ODsay 하루 30건 제한**: 처음 조사한 것과 달리 무료 호출이 하루 30건뿐이었습니다. 그래서 후보 장소를 3~5곳으로
   줄이고, 저장된 결과를 다시 쓰고, 호출 전에 몇 건이 필요한지 미리 알려주도록 하였습니다.
   또 시연 중 한도가 끝나는 상황에 대비해 ON/OFF가 가능한 테스트 모드를 만들었습니다.
   하지만 여러 명이 동시에 쓰면 금방 소진되기 때문에 실제 서비스로 쓰기에는 부족합니다.
2. **버스 막차가 1시간 차이 남**: 앱은 3217번 막차를 23:45로 계산했지만 네이버에서는 22:45였습니다.
   회차점(건대입구)에서 거꾸로 검색해 보고, 23:45가 기점이 아니라 회차점 쪽 막차라는 원인을 발견하였습니다.
   이후 막차 값이 하나뿐인 버스는 더 이른 쪽으로 계산하고, "확인 필요" 경고와 함께
   "막차로 꼭 도착해야 하는 곳을 지하철역으로 정하면 더 정확하다"는 안내를 띄우게 했습니다.
   하지만 버스 막차는 여전히 보수적으로 추정되기 때문에, 버스로 집에 가는 친구는 실제보다 일찍 헤어지게 됩니다.
3. **맛집 추천 기능이 쓸모없었음**: 카카오 API에는 별점과 리뷰가 없어서 추천 결과가 대부분 프랜차이즈였습니다.
   필요 없다고 판단해 과감히 제거했고, 대신 카카오맵에서 주변을 직접 볼 수 있는 링크만 남겼습니다.
   그리고 처음 기획 의도인 "막차 걱정 없이 늦게까지 놀기"로 돌아가 모임 시간 플래너로 방향을 바꾸게 되었습니다.

## 9. 알려진 한계

- ODsay 하루 30건 때문에 친구는 3명까지입니다.
- 소요시간은 평균 기준이며 실시간 운행 정보(지연, 임시 열차)는 반영하지 않습니다.
- 버스 막차는 추정이며 일부러 이른 쪽으로 계산합니다.
- 환승 3회 이상과 갈래 노선은 "확인 필요"로 표시합니다.
- 후보역은 고정된 45곳 중에서만 고릅니다.
- 캐시는 약 100m 단위로 공유됩니다.
- 배포하지 않았습니다.
