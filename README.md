# 🚇 오늘은여기서

수도권 친구들의 출발지를 넣으면, 대중교통 소요시간을 기준으로 모두에게 공정한 약속 장소(지하철역)를 추천하고, 귀갓길 막차까지 계산해 주는 Streamlit 웹앱입니다.

## 1. 프로젝트 소개

**목적.** 경기도에 사는 친구와 서울에서 만나면, 한 사람만 늘 멀리 오고 막차 때문에 일찍 헤어지게 됩니다. 막차 걱정 없이 늦게까지 놀고 싶어서 만들었습니다.

**대상 사용자.** 서울과 경기도에 흩어져 사는 2~3명의 친구 모임. 특히 "몇 시까지 놀 수 있지?"를 매번 직접 찾아보는 경기도 친구.

![정자역에서 귀갓길 막차를 계산한 화면](docs/images/README용사진/app_target_bokjeong.png)

위례 친구가 복정역까지만 가면 되는 경우, 이 모임은 23:24까지 놀 수 있다고 계산한 화면입니다.

## 2. 실행 방법

### 공통 준비

```bash
git clone https://github.com/jcy1109/oneul-yeogi.git
cd oneul-yeogi
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### API 키 없이 데모 실행

1. `.env` 없이 `streamlit run app.py`를 실행하면 **데모 모드**가 됩니다. API를 부르지 않고 `demo_data/`의 예시만 씁니다.
2. 사이드바 **저장된 예시 불러오기** → **약속 장소 추천받기** → 1위 정자역.
3. 첫 번째 친구의 "막차로 꼭 도착해야 하는 곳"에 `복정역`을 넣고 **🌙 막차 확인하기** → 평일 23:24 (빈칸이면 21:43).

### 키를 넣고 실제 실행

1. `.env.example`을 `.env`로 복사하고 두 키를 넣습니다.
2. ODsay 콘솔에 **실행하는 컴퓨터의 IP를 등록**합니다. 안 하면 인증 오류가 납니다.
3. `streamlit run app.py` 실행 후 사이드바의 테스트 모드를 끕니다.
4. **ODsay는 하루 30건**입니다. 추천 1번에 최대 10건, 막차 확인은 친구 1명당 최대 3건을 쓰며, 조회한 구간은 저장해 다시 부르지 않습니다.

### 테스트 실행

```bash
for f in test_*.py; do python $f; done
```

## 3. 주요 기능

1. **공정한 약속 장소 추천.** 출발지 중심에서 가까운 후보역을 고른 뒤, 친구별 실제 대중교통 시간으로 순위를 매깁니다.
   - ⚖️ 공평하게: 가장 오래 걸리는 친구의 시간이 짧은 순
   - ⚡ 빠르게: 모두의 이동시간 합이 짧은 순
2. **집부터 경로 안내.** 주소나 건물 이름으로 출발지를 받고, 집에서 첫 역까지 걷는 구간부터 갈아타는 곳까지 보여줍니다.
3. **모임 시간 플래너.** 친구별 출발 시각을 계산하고, 1위 역에서 각자의 귀가 목표 지점까지 막차를 거꾸로 계산해 "몇 시까지 놀 수 있는지" 알려줍니다.

## 4. 작업 과정과 주요 결정

- **10/14 뼈대:** 카카오 좌표 변환, 후보역 30곳, 출발지 중심점에서 가까운 역 고르기.
- **직선거리 → 실제 대중교통 시간:** 강남+수원의 중심점은 금정이지만 강남에서는 돌아가야 해서, ODsay 소요시간과 캐시, 한도 관리를 넣었습니다.
- **기준 3개 → 2개:** care, fast, equal을 실제 데이터(강남+수원)로 비교해 보니 equal이 care와 같은 결과를 냈습니다. 그래서 공평하게(fair)와 빠르게(fast)만 남겼습니다.
- **출발지를 역 → 집 주소:** 실제로는 집에서 출발하므로, 주소 검색 후 후보 3곳 중에서 고르게 바꿨습니다.
- **맛집 기능 제거 → 모임 시간 플래너:** 직접 써보니 맛집 결과가 대부분 프랜차이즈였습니다. 그래서 약속 시각과 친구별 출발 시각으로 방향을 바꿨습니다.
- **막차 전 "0단계":** 코딩 전에 실제 호출 6건으로 응답 형식을 확인해 설계 변경(종착역별 막차 표시, 버스 회차점)을 미리 찾았습니다.
- **"막차로 꼭 도착해야 하는 곳" 입력:** 마지막 구간은 택시로 갈 수도 있고, 버스 막차는 부정확합니다. 그래서 친구마다 목표 지점을 정하게 했습니다(복정역 23:24, 집 21:43).
- **제출 준비:** 키 없이 실행할 수 있도록 데모 모드와 `demo_data/`를 추가했습니다.

## 7. 효과적이었던 실천

1. **에이전트 보고를 그대로 믿지 않고 직접 대조하기**: 에이전트가 테스트 결과를 보고하면 바로 받아들이지 않고
   직접 검증했다. 좌표는 지도에서, 경로는 카카오맵에서, 막차는 네이버 시간표에서 확인했다.
   그 결과 에이전트가 "확정"이라고 했던 3217번 버스 막차가 실제와 1시간이나 차이 나는 오류를 발견했다.
2. **[여기에 두 번째 실천]**
3. **기능 하나마다 테스트하고 커밋하기**: 기능이 하나 완성될 때마다 테스트를 돌리고 GitHub에 커밋했다.
   덕분에 맛집 기능처럼 필요 없는 코드를 지울 때도 기록이 남아 있어서 부담이 없었고,
   새 기능을 넣은 뒤 이전 결과(복정역 목표 23:24 등)가 그대로인지 바로 확인할 수 있었다.

## 8. 어려웠던 점

1. **ODsay 하루 30건 제한**: 처음 조사한 것과 달리 무료 호출이 하루 30건뿐이었다. 그래서 후보 장소를 3~5곳으로
   줄이고, 저장된 결과(캐시)를 다시 쓰고, 호출 전에 몇 건이 필요한지 미리 알려주도록 했다.
   또 시연 중 한도가 끝나는 상황에 대비해 ON/OFF가 가능한 테스트 모드를 만들었다.
   하지만 여러 명이 동시에 쓰면 금방 소진되기 때문에 실제 서비스로 쓰기에는 부족하다.
2. **버스 막차가 1시간 차이 남**: 앱은 3217번 막차를 23:45로 계산했지만 네이버에서는 22:45였다.
   회차점(건대입구)에서 거꾸로 검색해 보고, 23:45가 기점이 아니라 회차점 쪽 막차라는 원인을 찾았다.
   이후 막차 값이 하나뿐인 버스는 더 이른 쪽으로 계산하고, "확인 필요" 경고와 함께
   "막차로 꼭 도착해야 하는 곳을 지하철역으로 정하면 더 정확하다"는 안내를 띄우게 했다.
   하지만 버스 막차는 여전히 보수적으로 추정되기 때문에, 버스로 집에 가는 친구는 실제보다 일찍 헤어지게 된다.
3. **맛집 추천 기능이 쓸모없었음**: 카카오 API에는 별점과 리뷰가 없어서 추천 결과가 대부분 프랜차이즈였다.
   필요 없다고 판단해 과감히 제거했고, 대신 카카오맵에서 주변을 직접 볼 수 있는 링크만 남겼다.
   그리고 처음 기획 의도인 "막차 걱정 없이 늦게까지 놀기"로 돌아가 모임 시간 플래너(출발 시각과 막차)로 방향을 바꿨다.

## 9. 알려진 한계

- ODsay 하루 30건 때문에 친구는 3명까지입니다.
- 소요시간은 평균 기준입니다.
- 버스 막차는 노선 정보로 추정하며, 일부러 이른 쪽으로 계산합니다.
- 환승 3회 이상과 갈림역을 지나는 갈래 노선은 "확인 필요"로 표시합니다.
- 후보역은 고정된 45곳 명단에서만 고릅니다.
- 캐시는 약 100m 단위라 가까운 출발지끼리 기록을 함께 씁니다.
- 실시간 운행 정보(지연, 임시 열차)는 반영하지 않습니다.
- 배포하지 않았습니다.

## 10. 채점용 핵심 파일

| 파일 | 역할 |
|---|---|
| `app.py` | Streamlit 화면. 입력, 결과 카드, 막차 표시 |
| `candidates.py` | 출발지 중심점에서 가까운 후보역 고르기 |
